# Runtime 性能诊断

Runtime 复用 OpenTelemetry tracer 和应用已有的导出配置。启动 Runtime 前配置好
TracerProvider 与 exporter 后，新增记录沿同一条观测通道发送；本功能不创建新的
Collector、存储或查询服务，也不自行改变采样策略。

## 请求与阶段记录

| 记录 | 范围 |
| --- | --- |
| `agent_server_request` | 接收 HTTP 请求到最终响应 body 发送完成 |
| `runtime.session.get` | 实际会话加载调用 |
| `runtime.session.create` | `/invoke` 中需要创建会话时的实际调用 |
| `runtime.runner.get` | 获取或初始化 Runner |
| `agent.execution.first_event` | Runner 首次产出事件，记录在请求 Span 上 |
| `agent.execution.finished` | Runner 迭代和关闭完成，记录在请求 Span 上 |
| `agent.execution.failed` | 执行失败，仅记录异常类型；请求 Span 仍到响应发送完成 |
| `http.response.first_body` | 首个非空 body 发送完成 |
| `http.response.incomplete` | 应用结束时没有完成响应，例如断开或取消 |

入站 `traceparent` / `tracestate` 用于接续上游 Trace。Runtime 请求是 SERVER Span，
阶段与 Agent 执行使用实际父子调用关系。不会从 baggage 推断租户或任务权限。
通过会话校验后才记录 `gen_ai.session.id`。不会用 Session ID 构造 Task ID。

`/run_sse` 可携带独立的 `agentkitDiagnosticRunId`（1—64 个字母、数字、下划线
或连字符），记录为请求属性 `agentkit.run.id`，用于匹配前端单轮诊断记录。
它不表示业务 Task ID，也不替代 ADK 的 `invocation_id`；恢复执行仍使用原框架字段。

首个执行事件可能是工具或状态事件，不能代替首 Token 或前端首次内容展示。
请求 Span 还包含流式发送，不应直接把它的结束时间当作 Agent 执行结束时间。
执行失败记录在请求 Span 上，错误响应发送完成后再结束该 Span。

## 与可观测能力的分工

可观测通道负责接收、保存和查询这些 Span，以及已有模型和工具调用记录。
性能诊断使用同一批记录定位会话加载、Runner 初始化、执行和响应发送等慢段。
阶段 Span 嵌套在请求内，耗时不能重复相加。

跨多轮的任务总耗时，需要任务状态服务提供受理、等待、恢复和完成记录；
前端首字耗时与本轮响应耗时，需要前端实际展示时点。Runtime 的阶段计时
不代替这些数据，也不把本地验证结果当作线上部署已生效的证据。

## A2A 协议任务关联

`AgentkitA2aApp` 在已有 `a2a_invocation` Span 上记录实际 RequestContext 的
`agentkit.task.id`，用于查询同一协议任务的执行。执行失败保留原始异常并完成
已有观测收尾。一次 executor 返回不表示跨轮任务最终完成；任务终态和人工等待
仍需从对应 TaskStore 与实际状态事件核验。此关联不增加新的上报通道。
