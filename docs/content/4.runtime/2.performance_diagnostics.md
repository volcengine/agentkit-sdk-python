# Runtime 性能诊断

Runtime 复用 OpenTelemetry tracer 和应用已有的导出配置。启动 Runtime 前配置好
TracerProvider 与 exporter 后，新增记录沿同一条观测通道发送；本功能不创建新的
Collector、存储或查询服务，也不自行改变采样策略。

## 请求与阶段记录

| 记录 | 范围 |
| --- | --- |
| `agent_server_request` | 接收 HTTP 请求到最终响应 body 发送完成 |
| `runtime.session.get` | 实际会话加载调用 |
| `runtime.session.create` | `/invoke` 中需要创建会话时的实际调用 |
| `runtime.runner.get` | 获取或初始化 Runner |
| `agent.execution.first_event` | Runner 首次产出事件，记录在请求 Span 上 |
| `agent.execution.finished` | Runner 迭代和关闭完成，记录在请求 Span 上 |
| `agent.execution.failed` | 执行失败，仅记录异常类型；请求 Span 仍到响应发送完成 |
| `http.response.first_body` | 首个非空 body 发送完成 |
| `http.response.incomplete` | 应用结束时没有完成响应，例如断开或取消 |

入站 `traceparent` / `tracestate` 用于接续上游 Trace。Runtime 请求是 SERVER Span，
阶段与 Agent 执行使用实际父子调用关系。不会从 baggage 推断租户或任务权限。
通过会话校验后才记录 `gen_ai.session.id`。不会用 Session ID 构造 Task ID。

`/run_sse`、标准 ADK `/run` 和 SDK `/invoke` 兼容入口可携带独立的 `agentkitDiagnosticRunId`（1—64 个字母、数字、下划线
或连字符），记录为请求属性 `agentkit.run.id`，用于匹配前端单轮诊断记录。
它不表示业务 Task ID，也不替代 ADK 的 `invocation_id`；恢复执行仍使用原框架字段。

`/invoke` 从 JSON 对象中读取此字段并从用户输入副本中移除；有 `prompt` 时仍只把
`prompt` 交给 Agent，无 `prompt` 时保留其余 JSON 输入。无效标识返回 400，不回显
原值，也不创建会话或运行 Agent。未传标识时保留旧行为。该能力不代表任意自定义
HTTP 服务已经支持此协议；调用方须确认实际部署的入口和 SDK 版本。
标准 ADK `/run` 仍由原处理器执行，保留恢复执行字段、路由依赖、响应过滤和
断连处理；成功返回后记录执行结束，不把原处理器的 499 断连响应标成成功。
不从收集完毕的事件列表反推首事件时间。仅支持已核验的 `req` 或 `req, request`
处理器签名，未知签名保留原路由并告警。Identity V1 仍拒绝 `/run`，本改动不扩大
其路由权限；启用该身份模式时沿用已授权的 `/run_sse` 或 `/invoke`。

请求 Span 同时记录 `agentkit.runtime.id`，来源是部署平台注入的
`MODEL_AGENT_CLIENT_REQ_ID=agentkit/<Runtime ID>`，不接受请求头指定资源身份。
此字段便于核对同轮执行来自哪个 Runtime，不代表部署快照或账号授权；
latest 配置更新时的工作区绑定仍需服务端核验实际执行证据。

部署平台提供 `_FAAS_REVISION_NUMBER` 时，请求 Span 将有效的非负 int32 Revision
记录为字符串属性 `faas.version`。该值在执行时从进程环境读取，不从浏览器、请求头
或控制台当前版本推算；缺失或格式无效时省略，不影响请求执行。它表示平台部署
Revision，不等同于应用业务版本，也不据此推断 Latest／Formal 等版本类型。
本地或其他部署未提供该字段时，不补造版本；该属性不作为账号授权依据。

首个执行事件可能是工具或状态事件，不能代替首 Token 或前端首次内容展示。
请求 Span 还包含流式发送，不应直接把它的结束时间当作 Agent 执行结束时间。
执行失败记录在请求 Span 上，错误响应发送完成后再结束该 Span。

## 与可观测能力的分工

可观测通道负责接收、保存和查询这些 Span，以及已有模型和工具调用记录。
性能诊断使用同一批记录定位会话加载、Runner 初始化、执行和响应发送等慢阶段。
阶段 Span 嵌套在请求内，耗时不能重复相加。

跨多轮的任务总耗时，需要任务状态服务提供受理、等待、恢复和完成记录；
前端首字耗时与本轮响应耗时，需要前端实际展示时点。Runtime 的阶段计时
不代替这些数据，也不把本地验证结果当作线上部署已生效的证据。

请求 Header 上报采用固定白名单：只保存规范化的 Content-Type、格式有效的
traceparent，以及长度受限的 x-request-id / x-faas-request-id。不会上报 Cookie、
API Key、平台注入的临时凭证或未知 Header，Content-Type 的附加参数也不保存。
标准 Server 与 Simple App 在写入 Span 时执行相同过滤，业务和鉴权仍接收原始
Header；W3C 上下文提取不受影响。此保护需要部署包含修复的 SDK 版本，不能清除
已有 Trace 中的历史数据。

平台提供 `_FAAS_FUNC_ID` 时，请求 Span 另外记录 `agentkit.runtime.function.id`，
用于区分不同物理函数的相同 Revision。只接受有界资源标识；缺少有效 Runtime 身份或
变量无效时不记录，不接受请求头覆盖。该字段不等同于业务版本，业务版本映射仍需
结合 Appo 的历史快照核对。来源字段沿用 [VeADK 的原生函数识别](https://github.com/volcengine/veadk-python/blob/405a9453027cf728a9ab09a1fa8eaf2780b9b4bc/veadk/cli/studio_vpc_network.py#L38)
与 VeFaaS 集成模板；具体部署是否提供该字段仍按实际执行验证。

## 执行时的资源配置

部署平台可通过 `AGENTKIT_RUNTIME_DIAGNOSTIC_CONFIG` 下发协议版本为 1 的公开配置。
请求 Span 记录以下已知值，未提供的值不猜测平台默认值：

| 属性 | 含义 |
| --- | --- |
| `agentkit.runtime.config.cpu_milli` | CPU 配置，单位毫核 |
| `agentkit.runtime.config.memory_mb` | 内存配置，单位 MiB |
| `agentkit.runtime.config.max_concurrency` | 单实例并发配置 |
| `agentkit.runtime.config.fingerprint` | 上述已知资源值的稳定指纹，用于对比配置 |
| `agentkit.runtime.target.type` | 已确认的物理函数目标 latest/formal；不是业务版本 |

只读取固定字段，不读取完整环境、凭据或镜像地址。缺少有效 Runtime 身份时不记录；
协议无效、字段重复或超出约束时忽略整份元数据，保持原请求行为。该配置由控制面在
创建、更新、复制发布时生成；SDK 支持不代表控制面已部署或历史执行已具备这些字段。
业务版本与部署 Revision 的历史对应仍须单独确认，不用当前 Latest 配置回填历史。

## A2A 协议任务关联

`AgentkitA2aApp` 在已有 `a2a_invocation` Span 上记录实际 RequestContext 的
`agentkit.task.id`，用于查询同一协议任务的执行。执行失败保留原始异常并完成
已有观测收尾。一次 executor 返回不表示跨轮任务最终完成；任务终态和人工等待
仍需从对应 TaskStore 与实际状态事件核验。此关联不增加新的上报通道。

独立 A2A 服务和标准 Harness 挂载的 A2A 服务均在实际 TaskStore.save 调用上
生成 `a2a.task.save` Span。保存成功后记录 `a2a.task.state.saved` 事件，附协议
状态和协议时间戳；保存失败只记录异常类型，不记录敏感错误正文。仍使用调用方
提供的 TaskStore；默认存储仍为内存。`input-required` 仅表示协议要求补充输入，
不自动判定为阻塞执行的人工等待；重复保存状态不作为新的状态转移计数。

## LangGraph Server 接入

LangGraph Server 的 AgentKit 适配入口 `/run`、`/run_sse` 和 `/invoke` 复用
`agent_server_request` 请求 Span 与 W3C 上下文提取，记录 `runtime.agent.execute`
子 Span，以及首事件、执行结束或执行失败事件。两层都记录实际请求的会话标识及
可选的 `agentkitDiagnosticRunId`，关联前端单轮记录；这些字段不作为鉴权依据。
重复构造适配器不会重复安装中间件，原生 LangGraph 路由不增加该层采集。

执行 Span 覆盖 AgentKit 适配流，包含等待 LangGraph 和流消费的时间；不会据此
拆分 LangGraph 内部模型、工具或排队阶段。内部阶段需复用对应框架的实际 Trace。
流返回中断或结束仅证明本次执行流结束，不能用作跨轮业务任务完成或人工等待结束。
